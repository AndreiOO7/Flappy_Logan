Привет!

Ниже — полная спецификация всех взаимодействий фронтенда с бэкендом для проекта Flappy Logan.

====================================================================
1. АУТЕНТИФИКАЦИЯ (auth.js)
====================================================================

--- POST /api/auth/register ---
Когда: При отправке формы регистрации (юзернейм + пароль).
Тело запроса:
{
  "username": "string (3-20 символов, латиница/цифры/underscore)",
  "password": "string (минимум 4 символа)"
}
Ожидаемый ответ (201):
{
  "success": true,
  "user": {
    "id": "uuid",
    "username": "string",
    "balance": 1000,
    "skins": ["bird-default", "pipe-default", "bg-default"],
    "createdAt": "ISO8601"
  }
}
Что делает фронт после ответа:
- Сохраняет user в localStorage (flappy_logan_user)
- Перерисовывает хедер (аватарка, юзернейм, баланс, дропдаун)
- Диспатчит событие auth:change — shop.js перезагружает скины
Ошибки: 409 (уже существует), 400 (валидация)

--- POST /api/auth/login ---
Когда: При отправке формы входа.
Тело запроса:
{
  "username": "string",
  "password": "string"
}
Ожидаемый ответ (200):
{
  "success": true,
  "token": "jwt-token",
  "user": {
    "id": "uuid",
    "username": "string",
    "balance": 1000,
    "skins": ["bird-default", "pipe-default", "bg-default"]
  }
}
Что делает фронт:
- Сохраняет user в localStorage
- Все дальнейшие запросы шлют Authorization: Bearer <token>
- В хедере появляется блок пользователя
Ошибки: 401
ВАЖНО: Поле skins обязательно должно быть в ответе — фронт использует его, чтобы:
- В магазине показывать "Куплено" для купленных скинов
- В инвентаре показывать список доступных скинов

--- GET /api/auth/me ---
Когда: При перезагрузке страницы (фронт восстанавливает сессию из localStorage).
Headers: Authorization: Bearer <token>
Ожидаемый ответ:
{
  "success": true,
  "user": {
    "id": "uuid",
    "username": "string",
    "balance": 1000,
    "skins": ["bird-default", "bird-red", "pipe-default", "bg-default"]
  }
}

--- PUT /api/auth/profile ---
Когда: При смене юзернейма или пароля в модалке профиля.
Headers: Authorization: Bearer <token>
Тело запроса:
{
  "currentPassword": "string (обязательно)",
  "newUsername": "string (опционально, новый юзернейм)",
  "newPassword": "string (опционально, новый пароль, мин 4 символа)"
}
Ожидаемый ответ:
{
  "success": true,
  "user": {
    "id": "uuid",
    "username": "string (возможно обновлённый)",
    "balance": 1000,
    "skins": ["..."]
  }
}
Что делает фронт: Обновляет user в localStorage и перерисовывает хедер.
Ошибки: 400, 401 (неверный текущий пароль), 409 (юзернейм занят)

2. МАГАЗИН (shop.js)
====================================================================

--- GET /api/shop/skins ---
Когда: При загрузке страницы магазина.
Ожидаемый ответ:
{
  "success": true,
  "skins": [
    {
      "id": "bird-red",
      "name": "Красный кардинал",
      "category": "birds",
      "price": 200,
      "image": "url-or-null"
    }
  ]
}
Категории: birds, pipes, backgrounds
Фронт группирует скины по категориям и рендерит табы.

--- GET /api/shop/user-skins ---
Когда: При загрузке магазина (если пользователь авторизован).
Headers: Authorization: Bearer <token>
Ожидаемый ответ:
{
  "success": true,
  "skins": ["bird-default", "bird-red", "pipe-neon"]
}
Фронт сверяет этот список с текущими скинами в магазине:
если скин есть в списке -> кнопка "Куплено" (disabled).

--- POST /api/shop/buy ---
Когда: Пользователь нажимает "Купить" на карточке скина.
Headers: Authorization: Bearer <token>
Тело запроса:
{
  "skinId": "bird-red"
}
Ожидаемый ответ:
{
  "success": true,
  "balance": 800,
  "skinId": "bird-red"
}
Что делает фронт:
- Обновляет user.balance и user.skins (+ новый skinId)
- Кнопка становится "Куплено" (disabled)
- Хедер обновляет баланс
Ошибки: 400 (скин не найден / уже куплен), 402 (недостаточно средств)

3. ИНВЕНТАРЬ (profile.js)
====================================================================

--- GET /api/shop/equipped ---
Когда: При открытии модалки инвентаря.
Headers: Authorization: Bearer <token>
Ожидаемый ответ:
{
  "success": true,
  "equipped": {
    "birds": "bird-red",
    "pipes": "pipe-neon",
    "backgrounds": "bg-space"
  }
}
Фронт показывает активный скин в каждой категории и подсвечивает его.

--- POST /api/shop/equip ---
Когда: Пользователь нажимает "Надеть" на скине в инвентаре.
Headers: Authorization: Bearer <token>
Тело запроса:
{
  "skinId": "bird-red",
  "category": "birds"
}
Ожидаемый ответ:
{
  "success": true,
  "equipped": {
    "birds": "bird-red",
    "pipes": "pipe-default",
    "backgrounds": "bg-default"
  }
}
Что делает фронт: Обновляет подсветку активного скина,
имя активного скина в заголовке категории.
Ошибки: 400 (скин не принадлежит пользователю, неверная категория)

  "balanceAwarded": 42,
  "newBalance": 1042
}
Фронт обновляет баланс в хедере.
Баланс начисляется 1:1 к очкам.

5. ЛОКАЛЬНЫЙ FALLBACK (важно!)
====================================================================

Фронт написан так, что при недоступности бэка (fetch падает с ошибкой)
он использует localStorage:

- Пользователи -> flappy_logan_users
  (JSON-объект { username: { password, balance, skins } })
- Сессия -> flappy_logan_user
  (текущий { username, balance, skins })
- Активные скины -> flappy_logan_active_skins
  ({ birds, pipes, backgrounds })

Это сделано для разработки. Когда бэк будет готов, фронт будет
использовать его автоматически — сначала идёт запрос к API,
если успех — используем ответ, если ошибка — fallback.
То есть достаточно просто запустить бэк по тем же эндпоинтам,
и всё заработает.

6. ФОРМАТ ОШИБОК (единый)
====================================================================

{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Human-readable description"
  }
}

HTTP статусы:
- 400 — Bad Request (валидация)
- 401 — Unauthorized
- 402 — Payment Required (недостаточно средств)
- 404 — Not Found
- 409 — Conflict (уже существует)
- 500 — Internal Server Error

7. JWT
====================================================================

- Payload: { userId: uuid, username: string }
- Exp: 7 дней
- Алгоритм: HS256
- Секрет: env JWT_SECRET
- Фронт шлёт: Authorization: Bearer <token>
- Фронт не хранит токен отдельно — он в объекте user в localStorage


====================================================================
8. РЕКОМЕНДУЕМАЯ СТРУКТУРА БД
====================================================================

Таблица users:
- id             UUID PK
- username       VARCHAR(20) UNIQUE (только латиница)
- password       VARCHAR (bcrypt hash)
- balance        INTEGER DEFAULT 1000
- created_at     TIMESTAMP

Таблица user_skins:
- id             UUID PK
- user_id        UUID FK -> users(id)
- skin_id        VARCHAR (например "bird-red")
- UNIQUE(user_id, skin_id)

Таблица user_equipped:
- user_id        UUID PK/FK -> users(id)
- birds          VARCHAR (активный скин птиц)
- pipes          VARCHAR (активный скин труб)
- backgrounds    VARCHAR (активный скин фона)

Таблица game_results:
- id             UUID PK
- user_id        UUID FK -> users(id)
- score          INTEGER
- played_at      TIMESTAMP

9. ВСЕ СТРАНИЦЫ, ГДЕ ЕСТЬ AUTH/HEADER
====================================================================

- index.html       -> main.js (initAuth)
- leaderboard.html -> main.js + leaderboard.js
- catalog.html     -> main.js (auth + shop)

На всех страницах в хедере:
- Не авторизован  -> "Войти" | "Регистрация" (data-auth атрибуты)
- Авторизован     -> аватарка + юзернейм (дропдаун: Профиль, Инвентарь, Выйти) | Баланс
